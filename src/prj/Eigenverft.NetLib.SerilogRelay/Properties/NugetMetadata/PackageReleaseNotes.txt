0.1.0 (2026-09-25)

- Created the SerilogRelay library in Eigenverft.NetLib.Infrastructure and migrated the revival context from Eigenverft.NetLib.SerilogCentralLoggingSink.
- Functionally migrated the archived AxonInsight SQLiteSinkHttp sender: durable local SQLite spool, restart recovery, background HTTP batching, sent-state updates, retention, retry/backoff, Retry-After handling, and shutdown flush.
- Preserved the historical wire behavior while renaming the pre-release public API to `SerilogRelaySink` and `.WriteTo.SerilogRelay(...)` so it matches the package purpose.
- Updated Microsoft.Data.Sqlite from the archived 9.0.6 reference to 10.0.12 to satisfy the repository vulnerability gate.
- Refreshed direct dependencies to current stable releases, including Serilog 4.4.0, Microsoft.NET.Test.Sdk 18.10.1, MSTest 4.4.1, and coverlet.msbuild 10.0.1.
- Corrected composite retention cleanup to use a valid single SQLite relative-time modifier while retaining SQLite as the source of the current clock.
- Stopped taking ownership of Serilog's process-global SelfLog configuration and restored HTTP status/transport diagnostics through caller-configured SelfLog.
- Replaced hand-written property JSON escaping with source-generated System.Text.Json while preserving the historical stringified Serilog property-value contract.
- Made synchronous/asynchronous disposal idempotent by sharing one shutdown task across repeated or concurrent callers; new events are rejected after shutdown begins.
- Added protocol version 1 event-level idempotency: every event receives a stable persisted `EventId`, retries reuse the same event identity, and `BatchId` remains per-attempt correlation metadata.
- Verified the v1 wire contract end-to-end against `Eigenverft.Service.CentralLogging` `/api/v1/logs` using the real relay and receiver implementations.
- Cleared the remaining Release-pack analyzer warnings with behavior-neutral cleanup: invariant persisted message rendering, explicit invariant numeric conversion, private cancellation-token parameter ordering, and direct schema placeholder replacement.
- Simplified the pre-release client API to fire-and-forget defaults: `.WriteTo.SerilogRelay(endpoint)` automatically resolves `ApplicationId`, LocalApplicationData spool directory, `SerilogRelay.db`, and the fixed internal `SerilogRelayEvents` table; optional `spoolDirectory`, `spoolFileName`, and `applicationId` overrides remain available.
- Added SQLite corruption recovery for `SQLITE_CORRUPT` / `SQLITE_NOTADB`: quarantine the corrupted spool (plus WAL/SHM when present), write best-effort corruption metadata, recreate the spool, persist a durable `spool_corrupted` relay event, and continue logging.
- Added a bounded non-corruption spool-failure fallback using the built-in `System.Threading.Channels`: normal delivery remains durable-first SQLite, while failed local writes enter a fixed 1024-event volatile emergency buffer that retries SQLite first and can rescue events directly over HTTP. Startup spool failures, ambiguous writes, overflow, and unresolved shutdown loss are explicitly handled and diagnosed through `SelfLog`.
- Replaced the inherited unconditional TLS certificate bypass with normal platform certificate validation by default; `dangerousAcceptAnyServerCertificate: true` is now an explicit per-sink opt-in that selects .NET's `DangerousAcceptAnyServerCertificateValidator`.
- Added automatic per-event producer identity: required `ApplicationId` and `ProcessId`, plus optional stable pseudonymous `MachineId` copied from the tested `PhysicalMachineBinding` implementation, are persisted in the local spool and transported unchanged to CentralLogging. The raw platform UUID and machine name are not sent.
- Verified the producer-identity contract end-to-end with the real CentralLogging receiver: `ApplicationId`, a 64-character hashed `MachineId`, and `ProcessId` arrive and persist through `/api/v1/logs`.
- Added 34 regression tests covering persistence, current-schema restart recovery, stable event identity, delivery, SQLite busy handling, HTTP failure/throttling paths, corruption recovery, idempotent shutdown, and sender lifecycle; the authored net10 library code is at 100% line, branch, and method coverage.
